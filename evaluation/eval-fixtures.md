## CSV 열

| 열 | 내용 |
|---|---|
| `question` | 한 번만 보내는 요청. `turns`가 있으면 비어 있음 |
| `turns` | JSON 배열 문자열 |
| `expected_route` | 비어 있으면 검사하지 않음 |
| `expected_source` | RAG 문항에서 `contexts`의 `doc_id`로 들어 있어야 할 문서 파일명 |
| `expect` | JSON 객체 문자열. 아래 판정 필드 |

## 판정 필드

`route`, `refused`, 후보 시간, 승인 대기는 응답 `trace`의 마지막 `decision` 단계에서 읽습니다. `trace`는 `[{step, input, output}]` 단계 목록입니다.

| 필드 | 뜻 |
|---|---|
| `expected_route` | 응답의 `route`와 같아야 함. `null`이면 검사하지 않음 |
| `refused` | 응답의 `refused`와 같아야 함 |
| `no_answer` | 찾는 대상이 없다고 답해야 함(거절과 다름) |
| `must_include` / `must_not_include` | 응답 `answer`에 들어 있어야 할 / 없어야 할 문자열 |
| `candidates` | 후보 시간 개수(`min`~`max`), 길이(`duration_min`), 기간(`from`~`to`). 모든 후보는 근무 시간 안이고 바쁨과 겹치지 않아야 함 |
| `registered_for` / `pending_approval_for` | 실행 후 일정이 바로 등록된 임원 / 승인 대기가 생긴 임원 |
| `approved` | 실행 후 승인 처리된 일정 제목 |
| `profile_created` | 실행 후 생긴 프로필 |
| `assignment` | 실행 후 생긴 담당 관계 |
| `unchanged_event` | 실행 후에도 그대로여야 하는 일정 제목 |
| `turns` | 같은 `thread_id`로 순서대로 보내는 여러 요청. 마지막 응답과 실행 후 상태로 판정 |
