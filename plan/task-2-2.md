# 계획: TASKS 2-2 직원·외부 참석자와 후보 없음 안내

## Context
2-2의 확인 항목은 m-05, m-06, m-21 세 문항입니다.
- m-05: 직원 참석, 30분, 후보 1~3개, 다음 주(11-02~11-06) 안
- m-06: 외부 인물 참석, 60분, 후보 1~3개, 답변에 "외부"
- m-21: `sec-choi`, 한도윤 상무가 다음 주 내내 출장, `no_answer=true`, 후보 0개

도구 단계는 이미 됩니다. `src/tools.py`의 `find_candidates`가 직원 바쁨을 반영하고, 외부 인물은 `notice`(EXTERNAL_NOTICE)를 붙이며, 빈 시간이 없으면 `no_answer`·`reason`을 돌려줍니다. `evaluation/check_tools.py`의 m-05·m-06·m-21 검사도 PASS입니다. 남은 것은 **Agent 단계**에서 두 가지를 확인하는 일입니다.
1. 모델이 도구에 인자를 맞게 넘기는가: 30분, 다음 주 날짜, 성명 전체
2. 답변에 안내 문구가 빠지지 않는가

이 중 2번은 지금 모델에 맡겨져 있습니다(`COORDINATION_PROMPT`의 "notice가 있으면 함께 안내"). 그런데 5-3에서는 3회 실행이 모두 통과해야 합니다. 그래서 CLAUDE.md 원칙("규칙 판정은 코드")에 따라 안내 문구를 **코드로 보장**합니다.

## 변경 파일
1. **`src/agent.py`** (바뀐 부분만)
   - `ensure_notices(answer, calls) -> str`(새 함수)
     - 도구 결과의 `notice`가 답변에 없으면 답변 끝에 한 줄로 덧붙입니다.
     - `no_answer`인 결과의 `reason`이 답변에 없을 때도 같은 방식으로 덧붙입니다.
     - 같은 문구는 한 번만 넣습니다. 문구는 도구가 준 그대로 쓰고, 모델 문장은 고치지 않습니다.
   - `run_query`에서 `get_text(messages[-1])` 결과를 `ensure_notices(..., calls)`로 감쌉니다.
   - `judge`·`build_trace`는 바꾸지 않습니다. `no_answer`와 `candidates`는 지금도 도구 결과로만 정해집니다.
2. **기준선에서 실패가 나올 때만** `COORDINATION_PROMPT`를 고칩니다(예: 30분을 넘기지 않음, 날짜 범위 오류). 어떤 실패였고 무엇을 고쳤는지는 결과에 적습니다.
3. **`TASKS.md`** 2-2를 `[x]`로 바꾸고, **`plan/task-2-2.md`**에 이 계획과 결과를 남깁니다.
4. 새 파일과 새 라이브러리는 없습니다. 검증 스크립트는 파일로 만들지 않고 인라인(heredoc)으로 실행합니다.
